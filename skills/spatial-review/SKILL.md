# Spatial review

Use the configured Spatial Collab MCP server for its private workspace. The runtime configuration or `SPATIAL_COLLAB_PROJECT` selects the primary project at process startup. If unavailable, use [private setup](../../docs/PRIVATE_CHATGPT.md) to initialize the dedicated runtime and an explicitly empty workspace or an existing project. Do not imply that an uncalled tool ran. Do not scan unrelated files or upload raw data without user authorization.

## Private connection and file workflow

Call `list_projects` with `project_id: null` to discover projects belonging to this connection. Use the chosen `project_id` on every later call; never infer project identity from a filename or the currently displayed canvas. The workbench file picker uploads a user-selected JSON snapshot or H5AD in checked chunks and imports it into a new independent project. Ask for missing measurement semantics; never guess the count layer or physical units. Files attached to a chat do not automatically become project input.

For retrieval, use the workbench's download action or `prepare_download`; the interface fetches chunks and checks the ZIP digest. A backend path or transfer ID is not a downloadable ChatGPT attachment. If the host blocks file selection or Blob download, explain the local workbench fallback. Large/native imports remain explicit CLI operations. `append_upload` and `read_download` are UI-only tools; do not generate file payloads in conversation.

Desktop plugin installation and local MCP success are distinct from a live cloud ChatGPT connection. The current delivery has no live ChatGPT acceptance. Without developer-mode/tunnel permissions, record that blocker and use the available local environment; never claim a tunnel, account authorization or iframe test occurred.

## Researcher and agent workflow

### Paired integration and review (v0.6)

Use `list_integrations` / `get_integration` to inspect external or local results with exact fit identities before discussing them. `submit_integration` queues RNA-only, protein-only and joint results on a pinned revision; `get_integration_job` reports success, failure or cancellation. Missing selected measurements fail explicitly. Simple balanced PCA is a non-spatial comparison baseline. SMOPCA is an optional bounded reference adapter, not a reproduction of all paper claims.

Use `inspect_integration` for exact viewport pages and `compare_integrations` for label-permutation-invariant comparisons. Rank disagreements as review candidates, not known errors. Create a shared selection by the returned exact IDs, inspect measured RNA/protein evidence, then use the existing researcher-authorized proposal workflow below. `filter_integration` explicitly retains original embeddings on a new inclusion revision; use a new fitting job for changed features/preprocessing/populations. Neither path establishes biological validity.

`run_integration_sensitivity` extends an existing frozen hypothesis plan across explicit backend and preprocessing alternatives without creating annotation revisions. Read all failures/unknowns via `get_integration_sensitivity`, not only favorable fits. `register_multimodal_object` records assay correspondences, derived layers, molecular relations or study designs; only strict paired data can enter the current paired backend. `compare_study` summarizes at subject level and retains condition/batch confounding. A stored correspondence or user attribution is not independent evidence. See [v0.6 guide](../../docs/V06_IMPLEMENTATION.md).

### Shared observations and annotation revisions

1. `get_capabilities` then `open_project` to obtain reader/host boundaries, current revision, data origin, measured genes, observation unit and view. State whether data are synthetic. Cell labels, spot annotations and bin annotations have different meaning. The canvas shows centroids, not tissue, boundaries or transcript positions. Use revision-pinned `query_observations` pages to find exact IDs by label, bounds or measured marker; no silent sampling or assumed cell identities.
2. `get_selection` to read the researcher's selection. If they request a new region, use `set_selection` with explicit cell IDs or polygon and expected revision. State slice, recorded frame and units, revision, selection size and centroid membership semantics. Unknown/pixel/array units permit expression, ROI and annotation exploration but cannot support micrometre radius analysis. Do not invent physical spacing. Sample-qualified IDs preserve original `sample_id` and `source_cell_id`; never move a raw barcode from another sample. Never infer selected cell IDs from a screenshot.
3. `inspect_selection` for the requested marker genes. A gene outside the imported measured scope is unmeasured, not a zero count. Use `get_feature_catalog` to review stable IDs and original symbols. An ambiguous symbol returns candidate IDs, not a summed signal; choose `feature_id:<ID>` when that identity is intended. Host cell previews contain only requested features; full counts remain in the source. Raw marker summaries are descriptive and do not establish cell identity. Explain alternative annotations and retain unresolved labels.
   Use `inspect_quality` for source-reported counts, nucleus/area fields, segmentation methods and imported-panel libraries. Missing/null is unknown, not zero; nucleus count or zero library is not a verified segmentation-error verdict. `query_observations` can select exact IDs with `attribute_filter={field,operator,value}`; unknown values never satisfy `ne`. Read source identity and `working_annotation` with the researcher: deterministic marker programs are automated working hypotheses, not expert identities.
4. `propose_revision` creates a preview only. Supported changes: label, inclusion flag, region tag. Present the exact selected objects/count, changed fields, rationale and affected result IDs. Existing source data is immutable. Use `get_proposal` to resume/review the same saved proposal in another interface; the local web UI and napari can present it to the researcher. Use `get_context` at task boundaries to detect shared state changes without repeatedly loading the matrix; it is a current-state token, not a full event log.
5. `apply_revision` only when the researcher has authorized this concrete proposal. Reuse an explicit authorization already given in context; avoid repeat prompts. Supply their stated reviewer attribution; never invent a person's name. Confirmation is recorded attribution, not authenticated identity or scientific sign-off. On a stale revision, refresh and make a new preview; do not silently rebase.
6. `run_comparison` with pinned base and target revisions and the same frozen ROI. Disclose `roi_induced` (neighbors restricted to ROI) or `whole_slice` (selected sources, all active imported neighbors), radius, labels and descriptive effect threshold. A cropped import is not the whole original slice; report `import_scope`. Inspect effect and denominator changes, composition and graph changes, and inconclusive states. A `stable` result concerns this metric at these settings, not every original scientific conclusion.
   For user-authorized computational what-if work before annotation commitment, use `run_sensitivity` on a pinned revision and exact selection. Each independent variant requires name, exact IDs, label/included changes and rationale; declare the radii in advance. This saves a result without modifying source/head or implying researcher approval. Report actual deltas even if the threshold classification is stable. Check halo coverage and background scope separately; a complete radius neighborhood does not establish representative tissue sampling. Do not invent a reviewer or commit a hypothetical variant just to obtain a comparison.
7. Prefer `create_hypothesis_plan` / `revise_hypothesis_plan` for an editable shared hypothesis table. Declare variants with exact IDs or explicit AND predicates, radii, scopes, background and threshold; missing selector values stay unknown. Freeze a version with `freeze_hypothesis_plan`, then execute that exact version with `run_hypothesis_plan`. Retain every grid row and its reason, including failed and unknown rows; present numerical changes and denominators even when the classification is stable. Edge weighting and source-equal weighting answer different descriptive questions; neither is a biological reference truth. Frozen settings are a computational record, not external preregistration or human sign-off. Later edits create a new draft. See [plan contract](../../docs/HYPOTHESES.md) for predicates and bounds.
8. `export_review_bundle` for reproducible local review; `compact:true` stores source plus overlays without duplicated count matrices. Use the workbench download action for a verified ZIP when remote retrieval is needed; explain local paths as local paths. Report revisions, parameters and missing evidence. `revert_revision` creates a new revision restoring an earlier overlay after researcher authorization.
9. For region composition or marker questions, use `run_region_comparison` with frozen foreground and explicit disjoint background (or declared same-slice complement). Distinguish most abundant from relative excess. Report raw/detection/panel-normalized denominators and changes; this is not differential-expression significance. A hypothesis about same-condition background requires the chosen imported slice/background actually match that condition.
10. For morphology questions, inspect `list_assets` and `inspect_asset` at exact cell IDs. Image and mask registration is an explicit local CLI/napari operation with source hash, frame, transform and native label-to-cell mapping; see [napari guide](../../docs/NAPARI.md). A centroid in a different declared mask is a discrepancy to inspect, not an automatic split/merge or true-coexpression diagnosis. Missing image, mask or correspondence remains unknown. Do not describe an unmatched image from another sample as evidence for this one.

## Interpretation boundaries

For v0.7 executable science, call `get_analysis_catalog` for method availability, input roles and accepted parameters; never infer that an installed package has passed validation. Use `prepare_analysis_input` to freeze explicitly declared species and revision/ROI, then `submit_analysis` with method, ordered immutable input IDs, parameters and seed. Reference/other-slice raw counts and their exact producer gene ID/symbol mapping are registered locally with `analysis import`; do not substitute cluster labels or invent a reference. `list_analysis_jobs` resumes durable tasks after reconnecting; `get_analysis_job`, cancellation and retries retain failures. `inspect_analysis_result` pages exact source observations and indicates whether they belong to the current project revision.

Choose by task: MOFA+ or spatial MEFISTO for paired multimodal factors; NNLS RNA contributions or Cell2location posterior abundance with an explicit cells/location prior; Harmony for expression batch correction; PASTE for full-overlap slice correspondence; SpaGCN or sparse spectral domains; Moran permutation/FDR for SVG; database-backed spatial LR hypotheses; PROGENy/ULM for separately inferred RNA pathway activity. Do not conflate these outputs. Read the result's numerical diagnostics, measured feature coverage and interpretation. Library availability, short training, batch mixing and same-data controls do not establish biological accuracy. See [scientific workflows](../../docs/V07_SCIENTIFIC_WORKFLOWS.md).

For paired proteins, start with `get_overview` and `list_assays`. `inspect_protein` takes the exact assay, revision, protein feature and optional shared selection. Antibody counts and intensities are separate measurement types; missing is not zero. Use `feature_id:<ID>` for ambiguous protein symbols. `run_protein_comparison` keeps the same frozen foreground/background across revisions; declare raw/log1p/asinh and the cofactor. Optional `rna_gene` returns paired raw RNA and panel-normalized RNA Spearman correlations, including pair counts and constant/insufficient unknowns. Retain all requested channels and both views, not just a favorable coefficient. This is exploratory concordance, not significance, cell fractions or causal regulation. Label changes may alter label composition without altering an all-label protein mean; inspect inclusion and label denominators in the full record. Exported bundles include immutable protein measurements and can be recomputed offline. Protein ingestion is a local `register-protein` operation with exact sample/original-ID/XY mapping; no nearest-neighbor pairing, silent intersection or antibody alias guess. See [protein guide](../../docs/PROTEOMICS.md).

For large datasets, use `list_atlases` / `get_atlas_view` on the explicitly chosen atlas. Each atlas retains its own source, sample and coordinate frame; it is not automatically the editable primary slice. Dense views return all-object density aggregates, never sampled cells. Zoom for exact points, transcript source IDs/quality/assignment, or cell/nucleus polygons. `freeze_atlas_roi` creates an exact sparse input for analysis without removing algorithm-specific budgets. `list_pyramids` / `get_pyramid_tile` expose explicitly registered native TIFF pyramid planes and affine world corners; registration is not evidence of alignment accuracy. See [large-data and study guide](../../docs/SCALABILITY_AND_STUDY.md).

For a multi-subject continuous outcome, freeze the researcher-declared design with `register_study_design`, then call `run_study_inference` with exact per-section source/run bindings and a complete metric family. Welch/paired tests use subject means; mixedlm uses subject random intercepts and declared batch/covariate terms. Never treat spots or sections as independent patients. Preserve missing subjects, confounding, nonconvergence, singularity and untested family members. Report effects/intervals and p/q together; MixedLM inference is asymptotic, not small-sample corrected. Raw counts or untransformed proportions require a different model. `list_study_analyses` returns stored designs and results. No computational plan is external preregistration or human sign-off.

- A project has one editable primary slice; v0.7 analysis inputs can explicitly include additional slices and a single-cell reference. Cells, transformed copies and multiple ROIs are not patient replicates.
- Neighbor fraction above abundance is a descriptive metric, not a calibrated enrichment test, p-value, communication mechanism or clinical conclusion.
- Absent labels, no edges or missing evidence must remain inconclusive. A completed computation never promotes a claim to biological validation.
- Region tags are annotations; changing a tag does not redefine a frozen ROI. Explicitly capture a new selection if the researcher changes region membership.
- Only this plugin's recorded runs receive automatic stale status. External analyses are not known to its dependency tracking; require their own rerun.
- Native tiled TIFF pyramids and 2-D molecule/boundary layers are supported through explicit atlas registrations; segmentation editing, cloud OME-Zarr and arbitrary command execution remain outside this plugin. Cross-patient inference requires its own declared study/model, not simply cross-sample integration. Doublet, follicle or morphology claims need additional evidence, not marker coexpression alone.
- `Unannotated` is an exploration placeholder, not an inferred cell type. Continue marker/ROI inspection; never report it as a validated population.
- Synthetic task checks and offline replay establish software behavior only; they are not SpatialBench scores, real-host model acceptance, independent biology or human-efficiency evidence.
- For Moran/LR, offer `create_analysis_power_plan` before `submit_analysis` and link its `power_plan_id`. Declare graph/family/BH rank, model, target power, simulation budget and rationale. Report exact permutation resolution separately from model-conditional grid MDE and its Monte Carlo intervals. Do not report zero FDR discoveries as absence of biology, call retrospective plans prospective, or optimize BH rank after seeing results to manufacture power. See [power contracts](../../docs/POWER_AND_METHOD_CONTRACTS.md).
- Use the catalog/result `method_contract`: internal numerical methods own stated calculations and numerical checks; external adapters own frozen input, invocation, environment/output integrity and boundaries, not upstream algorithm correctness. LIANA resource use is distinct from the custom spatial LR statistic; legacy results remain unclassified rather than retroactively endorsed.
- Tool summaries, selected cell IDs and view coordinates can reach the host model. Local storage alone does not imply no data transmission.
