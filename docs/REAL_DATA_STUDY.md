# 真实数据驱动的测试、科研复核与改进

2026-09-20 · Spatial Collab 0.3.0-alpha.1 · 本机真实数据工程／描述性分析试验。

**已经用此前下载的真实 Xenium 淋巴结数据完成一次可复算的协作研究演练，并据此修改了插件。** 数值结果支持的结论很有限：在固定窗口、工作标签、三个半径和三个明确假设下，指定邻域指标均未跨越预设 +0.1 阈值。它不证明标签正确、分割正确、没有细胞联系或科研效率已经提高。

## 输入与问题

研究情境：研究者发现一片组织中的多核、无核或标记证据较弱对象，想知道“把它们改为不确定，或在假设分析中排除，会不会改变 T 标记程序到 B 标记程序的邻域判断？”Agent 必须引用同一来源、选区、标签规则与参数，并把假设结果与真正的注释提交分开。

输入是已下载的 `cells.csv.gz` 和 `cell_feature_matrix.h5`。直接核对发现 708,983 个细胞、4,624 个表达基因，以及不能并入表达分母的控制／codeword 特征。[10x 官方数据页](https://www.10xgenomics.com/datasets/preview-data-xenium-prime-gene-expression)说明它来自一位供者的 FFPE 反应性淋巴结，是开发版试剂与分析流程的预览数据。原生坐标及 QC 字段解释依据 [Xenium 输出规范](https://www.10xgenomics.com/support/software/xenium-onboard-analysis/latest/analysis/xoa-output-understanding-outputs)。文件清单、来源限制、哈希和另外两类数据的审查见 [输入审计](REAL_DATA_INPUT_AUDIT.md)。

没有采用旧的 15,000 细胞派生子集：其生成过程包含分层抽样、病理标签自动拟合与仿射参数，不能用作均匀邻域、独立真值或确认的病理区域。

在查看标记结果前，按几何范围选定 600 × 600 µm 连续窗口 `[2700,2700,3300,3300]`，完整保留 7,725 个细胞及全部表达基因，不抽样。分析 ROI 为内部 `[2800,2800,3200,3200]`，共 3,383 个细胞，外围保留 100 µm 邻居范围。预先声明半径为 15、35、75 µm，阈值为 0.1。这是本次运行前保存的方案，不是外部独立预注册，也不是代表性组织抽样。

## 从真实输入发现的问题及已经完成的修改

| 实际触发的问题 | 完成的改进 | 仍有的边界 |
|---|---|---|
| 原版对 708,983 个细胞整表导入失败，无法直接进入协作 | Xenium H5 按显式窗口流式检查全源 ID，只切出选中稀疏列；保留所有表达基因与完整来源范围 | 选中窗口仍受 100k 对象／2M 非零项预算约束；不是整片大数据引擎 |
| CSV 的 `nucleus_area=NaN` 导致真实输入失败 | 明确缺失 token 转为 null；保留 11 个源 QC 属性；无穷、畸形数字继续拒绝 | QC 记录不证明分割正确；当前不查看原图或掩膜 |
| 只看 marker 无法复核多核／无核或零表达库 | 新增 `inspect_quality` 和网页只读 QC；按字段条件分页得到确切 ID | 没有通用 QC 分数或自动剔除结论 |
| 原有流程倾向先提交注释再算前后差异 | 新增 `run_sensitivity`：同一基线上的独立假设 × 半径，保存结果与完整参数，不创建新版本 | 假设不是研究者批准；真正改变注释仍用具体提案／确认流程 |
| 导入窗口可能在页面被理解为整张组织 | 工作台展示窗口和来源身份，使用“全导入窗口”；结果记录半径邻居是否可能被截断 | 完整邻居搜索不消除局部背景或选区偏差 |
| 大量基因未被该靶向面板测量 | 保留 `unmeasured`；实际测试 CD3D、TRAC、LYZ、VWF、JCHAIN、C1QA 都不能当成 0 | 六基因工作分组不能覆盖组织所有细胞类型 |
| 一次导入调用误填了 `human-colon-cancer-xenium` | 保留错误项目与失败 addendum，用正确 `xenium-prime-reactive-lymph-node` 新建不可变项目；界面突出来源与自动工作标签 | 哈希和计数一致不能验证填写的组织身份；需要对照来源记录 |
| 不完整窗口也可能被误判为半径覆盖完整 | 仅在明确无抽样、全质心规则、正确单位／数量／范围的窗口声明下判断 coverage；选择必须匹配源哈希 | 元数据仍是声明；外部导入不能因此获得真实性认证 |

只读 QC 实测：导入表达库中位数 267、四分位范围 169–359；4 个表达库为零。核面积有 98 个明确 null，核数量有 98 个实测零，两者语义不同。590 个对象的核数不为 1，其中 492 个大于 1。它们是敏感性分析对象，尚未被证实是 doublet 或错误分割。

## 工作标签与假设的确切含义

使用实际存在的标记：B 程序为 `MS4A1/CD79A/CD79B`，T 程序为 `CD3E/CD3G/CD2`；至少 2/3 个基因原始计数 ≥1 时程序为阳性。两程序均阳性记为 `Mixed_program`，均不满足记为 `Unresolved`。原始无注释项目保持不变；另建工作项目，并记录规则、源项目哈希和“未验证细胞身份”，没有虚构研究者署名。

| 工作组 | 600 µm 导入窗口 | 400 µm 分析 ROI |
|---|---:|---:|
| B_program | 1,798 | 799 |
| T_program | 1,074 | 401 |
| Mixed_program | 300 | 121 |
| Unresolved | 4,553 | 2,062 |

ROI 中 60.95% 未归组。这直接限制了对组织细胞构成的解释；不能把它们强制分配身份来改善演示。工作组定义 marker 在组间有差异，部分是由定义自身造成的循环性，不能拿来验证注释准确率。

三个假设分别从同一基线开始，既不串联也不覆盖源数据：

1. 核数不为 1 的对象改为 `Uncertain`：窗口 590 个，ROI 252 个。
2. 相同 590 个对象暂不纳入分析：独立排除假设，不是 QC 建议。
3. **在已经属于 B_program 或 T_program 的单程序分组中**，恰为 2/3 标记支持的对象改为 `Uncertain`：窗口 2,008 个，ROI 852 个。Mixed_program 保持不变，不是对所有阳性／混合对象实施全面重注释。冻结方案的简写在实现时具体化为这一范围；确切 ID 与改变记录均保留。

## 实际结果与分母

主指标是：ROI 内当前纳入的 T_program 来源对象，其半径内指向 B_program 的边数／所有非自身邻居边数，再减去候选背景中的 B_program 丰度。它按邻居边计权，密集位置和高邻居数来源会贡献更多；不是每个来源细胞的等权均值，更不是校准的富集检验。

下表使用保留外围邻居的全导入窗口背景，单位为百分点（pp）；阈值是 **+10 pp**。

| 情形 | 15 µm | 35 µm | 75 µm |
|---|---:|---:|---:|
| 工作标签基线 | −4.510 | −3.753 | −2.690 |
| 核数不为 1 → 不确定 | −3.580 | −3.022 | −2.223 |
| 核数不为 1 → 排除 | −3.767 | −3.268 | −2.444 |
| 单程序组要求三个 marker | −1.870 | −2.746 | −1.505 |

9 个主比较的阈值判断都保持“未达到”，但指标最多移动 **2.641 pp**，不能简写为“修改没有影响”。额外 9 个 ROI 内部图比较也未跨阈值，最大移动 3.511 pp。ROI 内部图删去了外围邻居，同时改变背景定义，是另一个空间问题；两种范围的差别不是生物学处理效应。

例如 35 µm 的主分析：

| 情形 | 来源对象 | 目标边 / 所有来源边 | 观察比例 | 背景比例 | 超额 |
|---|---:|---:|---:|---:|---:|
| 基线 | 401 | 6,790 / 34,775 | 0.195255 | 1,798 / 7,724 = 0.232781 | −0.037526 |
| 核数不为 1 → 排除 | 364 | 5,559 / 29,057 | 0.191314 | 1,598 / 7,134 = 0.223998 | −0.032684 |

排除改变了来源、邻居与背景分母，不能只比较最终一个分数。每种假设的这些分母已导出到 `metric-denominators.csv`；所有确切 ID、基线与变更后指标都在结果 JSON 中。

**允许的表述**：在这份真实输入、这个固定区域和工作规则下，所测试的三种假设均未改变指定阈值判断。**不允许的延伸**：真实细胞身份得到验证、分割无需修订、T/B 不存在联系、整片组织或其他患者结论稳定。负的描述性超额也不证明空间排斥；仍存在区域异质性、混合／未归组对象和边计权等解释。

## 实际可复核产物与验证

本机工作目录为 `projects/real-data-review/study-v03-complete`：

- `working-project/`：真实输入的自动工作标签项目，仍只有 1 个版本，没有提交任何假设。
- `frozen-plan.json`、`declared-variants.json`、`study-receipt.json`：方案、确切假设和结果收据。
- `sensitivity-whole_slice.json`、`sensitivity-roi_induced.json`：18 个比较及完整前后记录。
- `metric-denominators.csv`、`sensitivity-summary.csv`：便于外部复核的数值表。
- `quality-full-window.json`、`quality-roi.json`、`marker-availability.json`：QC、面板覆盖与未知值。
- `real-data-sensitivity.png/pdf`：空间分布、ROI/外围范围及半径敏感性图。
- `exports-and-replay.json`：两份真实分析审阅包的完整性与离线复算结果，均 matched。

独立实现的检查没有调用插件 `_evaluate` 或 KDTree：直接逐来源计算欧氏距离，重算 **36 条前后数值记录**，全部一致；所有 7,725 个工作标签按原始计数重新计算一致。导入检查逐项验证所有 ID／坐标、逐细胞总数，并在参考输出生成前固定了空间极值和随机十个细胞，直接核对原始 H5 的全部表达列；相关 receipt 位于该目录上一级。

在本机一次运行中，完整窗口打开约 2.06 秒；共享状态查询约 35–40 ms；QC 约 2.25–2.35 秒；一个 3 假设 × 3 半径计算约 3.64–3.82 秒；单次离线复算约 6 秒。这些是有界窗口的一次墙钟记录，没有做重复测量、内存性能基准或研究者对照，不能据此宣称节省多少科研时间。

复现分析（新输出目录；已安装项目或设置 `PYTHONPATH=src`）：

```powershell
python scripts/real_data_study.py --input-project projects/real-data-review/xenium-lymph-node-window --output projects/my-real-rehearsal --plan projects/real-data-review/study-plan.json
python scripts/plot_real_data_study.py projects/my-real-rehearsal
python -m spatial_collab serve --project projects/my-real-rehearsal/working-project --port 8768
```

绘图需要 `pip install -e ".[figures]"`。脚本拒绝覆盖旧输出。初次脚本调用的本地 import 路径和函数参数重名错误已修正，失败产生的 `study-v03` 中间项目保留；最终完整运行是 `study-v03-complete`。

## 下一步最值得解决的科研不足

| 优先级 | 真实情境中的不足 | 下一步的可验收结果 |
|---|---|---|
| 高 | 看到多核／混合表达，仍看不到组织与分割掩膜 | 接入已有 napari 的图像／分割与同一坐标对象，研究者能定位同一 cell，区分相邻细胞、合并分割和真实共表达；没有图像时明确不可判定 |
| 高 | HER2ST 与 SPOTS 的阵列坐标缺物理标尺，当前所有导入都要求 µm | 分离表达／阵列探索与物理距离能力：未知单位可做受限浏览和 marker 复核，物理半径仍需有证据的标定；本轮没有擅自填造间距 |
| 高 | SPOTS 两片共享 2,158 个 barcode；各有 38 个重复 gene symbol，产生 40 条额外重复行 | 采用 sample-qualified identity、稳定特征 ID 与可审阅的符号映射，不能把重命名或静默合并当成生物学解决方案 |
| 中 | 只检验人工选定的少数假设；稳定标签可能掩盖量值和分母变化 | 增加研究者可编辑的假设表、差异排序及参考方法对照；保持预声明参数、保留失败／未知，不择优报告 |
| 中 | 尚无宿主模型与科研人员的真实任务对照 | 同一任务比较手工、Agent、研究者+Agent 的完成时间、校正次数、漏检与错误接受，沿用现有任务框架；本次不是 SpatialBench 成绩或模型能力测试 |

本轮把真实失败转成了可用修复，也保留了未解决的数据与科学边界。完整组织、多供者推断、自动准确注释、分割真实性和人机效率优势仍未建立。
